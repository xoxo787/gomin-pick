# 차별화 후보 · 검토 초안

아래는 구현·검토할 후보이며 최종 제품 방향은 아직 정하지 않았다. 기능이 시제품에 포함되어 있어도 사용자 채택 결정이나 효과 검증으로 간주하지 않는다.

## 1. 같은 기준의 단위가격 비교

용량과 가격을 함께 확인한 제품을 10ml, 10g, 1ea별로 나누어 비교한다. 총가격만으로 다른 크기의 제품을 비교할 때 생기는 혼동을 줄이려는 제안이다. 기준 단위가 다른 제품끼리는 비교하지 않고, 값이 없으면 계산하지 않는다. 공통 계산식은 [검사기](../scripts/lib/validate.ts)와 [타입 계약](../src/types.ts)에 연결되어 있다.

검증할 것: 실제 사용자가 총가격과 단위가격을 구분하는지, 미확인 값의 의미를 이해하는지.

## 2. 비슷한 핵심 성분의 더 저렴한 대안

확인된 `key_ingredient_ids`가 겹치고 같은 기준 단위의 가격이 더 낮은 제품을 대안 후보로 제시한다. 성분 공통점과 가격 차이를 함께 보이려는 제안이다. **성분이 겹친다고 효과가 같지 않다.** 함량·제형·전체 조합·사용법이 다를 수 있고, 비교하지 못한 성분은 없다고 단정하지 않는다.

검증할 것: 출처가 핵심 성분을 뒷받침하는지, 같은 제형이나 대체 가능성을 섣불리 추정하지 않는지.

사용자 결정: ( )

## 3. 확인된 전성분에 한정한 민감 정보 필터

확인한 전성분 출처가 있을 때만 향료·에탄올 포함 여부를 필터에 활용한다. 미확인 값은 `null`로 유지하고 미포함 확인 제품과 구분한다. 특정 성분 유무만으로 모든 민감 피부에 맞는 제품이라고 판단하지 않는다.

검증할 것: 전성분 출처와 확인 범위가 일치하는지, 정보가 없는 제품이 확정 정보처럼 표시되지 않는지.

## 4. 카드마다 근거·출처·확인일

각 제품의 짧은 선택 근거, 어워즈/보도/공식 발표 출처, 확인일을 같은 카드에서 열어 볼 수 있게 한다. 데이터 계약의 `rank_basis`, `source_urls`, `evidence`, `checked_at`과 [데이터 검사기](../scripts/validate-data.ts)가 이 표시를 뒷받침한다. 과거 자료의 큐레이션 순서를 현재 전체 시장 순위로 설명하지 않는다.

검증할 것: 근거의 시점과 순위 범위가 읽히는지, 출처 링크가 제품에 관한 실제 주장과 연결되는지. 자동 형식 검사만으로 출처 내용까지 검증되지는 않는다.
